# 公众号 HTML 编辑器

使用本技能提供的本地服务器，不要为每篇文章临时编写一套编辑代码。

## 运行要求

- 仅支持 Windows 10 和 Windows 11。
- 需要 Python 3.10 或更高版本，命令名为 `python`，也可以使用 Windows 的 `py` 启动器。
- 安装插件根目录 `requirements.txt` 中的依赖。
- 编辑和复制可以单独使用；推送草稿箱还要求相邻的 `wechat-draft-publisher` 技能、公众号接口权限和 IP 白名单。

## 新建 HTML 的默认位置

用户指定保存路径时，使用用户指定的路径。用户提供已有 HTML 时，直接使用原文件，不能另存到默认目录。

新建文件统一使用 `scripts/create_article.py`，不要自行拼接另一套路径规则。已有文件仍由编辑器直接打开。

1. 用户明确指定文件路径时直接使用，不插入额外目录；相对路径以当前任务工作目录为基准。指定文件已存在时拒绝覆盖，新建操作不能擅自改名；如果用户要求编辑已有文件，直接打开编辑器。
2. 未指定路径时，读取当前任务工作目录中的 `.wechat-publishing.json` 的 `article_dir`。相对目录以该工作目录为基准，也支持绝对目录。不搜索父目录，不使用技能目录、插件目录或缓存目录作为项目根目录。
3. 没有配置时，文章根目录就是当前任务工作目录，不再添加 `公众号文章`。配置格式错误时报告错误，不静默回退。
4. 在文章根目录创建 `YYYY-MM-DD-标题\标题.html`，日期使用本机当前日期。标题优先使用用户确认的标题，否则提取 HTML 中的第一个 `h1`，再尝试 `title`，最后才使用 `未命名文章`。
5. 脚本清理 Windows 文件名非法字符和末尾空格、句点，并处理保留设备名。默认路径遇到重名时依次使用 `标题-v2.html`、`标题-v3.html`；使用独占创建避免覆盖。
6. 把脚本返回的绝对路径报告给用户，并将同一路径传给编辑器启动器。

项目可选配置（`.wechat-publishing.json`）：

```json
{
  "article_dir": "公众号文章"
}
```

该配置保留原来的目录结构。也可设置为 `公众号`、`内容/待发布` 或绝对路径。没有配置时，例如工作目录为 `E:\obsidian-vault`，日期为 `2026-09-05`，标题为 `文章标题`，输出为：

```text
E:\obsidian-vault\2026-09-05-文章标题\文章标题.html
```

从 Codex 提供的技能路径解析 `$skillRoot`，先将生成的完整 HTML 写入临时内容文件 `$source`，然后调用：

```powershell
$creator = Join-Path $skillRoot 'scripts\create_article.py'
$result = python $creator --source $source --project (Get-Location).Path | ConvertFrom-Json
$article = $result.path
```

有明确标题时加 `--title '文章标题'`；有明确文件路径时加 `--output '指定路径.html'`。只有退出码为 0 时才继续启动编辑器。

## 启动编辑器

1. 确定需要编辑的 `.html` 文件绝对路径，并确认文件存在。除非用户明确要求，否则不要改写文章内容或样式。
2. 检查文档是否包含 `<article>`、`#article` 或 `<main>` 正文根节点。
3. 从 Codex 提供的技能路径解析当前 `wechat-html-editor` 目录，将其保存为 `$skillRoot`。禁止假设用户名或安装目录。
4. 使用技能自带的 PowerShell 启动器。启动器会安全处理空格路径、选择可用端口、隐藏后台窗口并等待健康检查。

```powershell
$article = 'C:\文章\article.html'
$launcher = Join-Path $skillRoot 'scripts\start_editor.ps1'
$result = & $launcher -Article $article
$result
```

5. 读取启动器返回的 JSON，在可用浏览器中打开其中的 `url`，并向用户说明访问地址和正在编辑的目标文件。只有用户明确要求系统默认浏览器时才传入 `-Open`。

用户要求指定默认草稿封面时，给启动器增加 `-Cover 'C:\图片\cover.png'`。未指定时，发布器会先在文章同级目录查找最新的 `公众号封面-v*.png/jpg/jpeg`，再查找 `公众号封面.png/jpg/jpeg`。用户始终可以在发布窗口中另选封面。

不要通过 `file:///` 地址打开编辑页面。浏览器无法从本地文件页面可靠地覆盖原文件；本机服务器负责连接浏览器编辑操作和文件保存。

## 编辑器功能

- 页面打开后正文立即进入可编辑状态，不需要先点击按钮。
- 正文输入、插入或替换图片、调整图片尺寸和位置后，停止操作约 1 秒会自动保存。
- 编辑器不显示编辑开关和保存按钮，正文始终保持可编辑。
- 按 `Ctrl+S` 可以立即保存，不必等待自动保存计时结束。
- 页面存在尚未保存的修改时，关闭或刷新会触发浏览器提醒；页面切换到后台时也会尝试立即保存。
- `插入图片` 用于在最后一次光标位置插入数据网址（Data URL）图片。
- 点击图片后，显示替换、移动、宽度、对齐和删除工具。
- 点击选中图片后，按 `Delete` 或点击 `删除图片` 可移除该图片并自动保存；不会删除同段文字或其他图片。在发布表单中输入、切换文字光标后，快捷键不再作用于先前选中的图片。
- 拖动图片区块可以调整顺序，也可以使用 `上移` 或 `下移`。
- 本次编辑器会话第一次保存时创建 `<file>.bak` 原始备份；后续自动保存和 `Ctrl+S` 保存不会覆盖这份会话原始备份。
- `复制到公众号` 会复制计算后的文字排版和表格样式，同时去除固定桌面宽度，并以 `height:auto` 保持图片自适应。
- `推送到草稿箱` 会打开发布窗口，读取本地加密凭据，测试草稿权限，按需选择封面，上传正文图片并创建微信公众号草稿。此按钮依赖相邻的 `wechat-draft-publisher` 技能。
- 发布窗口不显示摘要输入框，也不提交自定义摘要；由微信按默认规则从正文生成摘要。

## 发布默认值

发布窗口支持为当前公众号 AppID 保存以下账号级默认值：

- 默认作者，最多 16 个字符。
- 默认阅读原文链接，可以留空；填写时必须是有效的 HTTP 或 HTTPS 地址，UTF-8 编码后不超过 1KB。
- 默认开启评论，新配置默认为开启。

用户首次填写后点击 `保存账号设置`，验证连接并保存配置。`检查账号连接` 只检查连接，不保存设置、不创建草稿。以后打开发布窗口时自动填入这些值，每篇文章仍可临时修改。默认值属于普通发布设置，与 AppID 一起保存在本地配置中；AppSecret 继续单独使用 Windows DPAPI 加密。

微信 `draft/add` 草稿接口没有原创声明字段。不得声称插件已经自动声明原创；需要原创声明时，草稿创建后由用户在公众号后台完成。

注入的工具栏和脚本只存在于本机服务器提供的编辑页面中。保存时必须从源 HTML 中清除这些编辑器内容。

## 验证

启动或修改编辑器后，完成以下检查。

1. 加载本机地址，确认页面标题和文章正文正常显示。
2. 确认正文加载后已经可以直接编辑，工具栏中没有编辑开关和保存按钮。
3. 只有获得修改授权时才在测试文件中进行可恢复的小改动；停止输入约 1 秒后，确认状态显示自动保存成功，源文件已更新且 `.bak` 仍是会话开始前的内容。
4. 再做一次修改并按 `Ctrl+S`，确认立即保存成功。
   在独立测试文件中验证：选中图片后按 `Delete`，仅该图片被移除，周围文字和正文根节点保留，自动保存成功；在表单输入框中按 `Delete` 不误删正文图片。
5. 测试 `复制到公众号`，确认页面显示复制成功。
6. 使用约 `390×844` 的移动端视口，确认首段没有与下一标题重叠，图片没有超出正文宽度。
   打开发布弹窗，确认遮罩覆盖整个视口、顶部关闭按钮和底部操作可见；超长表单仅内部滚动。弹窗独立于工具栏，保存时仍需移除弹窗及页面滚动锁定状态。
7. 检查浏览器错误。保存接口或界面出现异常时，不得声称验证成功。
8. 确认 `/__wechat_editor/health` 返回 `draftPublisher: true`。如果本机已经保存凭据，可以测试 `draft/count`；除非用户明确要求创建真实草稿，否则验证时不得点击 `创建草稿`。

## 安全要求

- 服务器只能绑定到 `127.0.0.1`。
- 保存请求必须携带服务器为本次运行生成并注入的令牌。
- 使用响应内容安全策略阻止文章中已有的脚本，只允许带有效随机数（nonce）的编辑器运行时代码。存在已保存发布凭据时，不得削弱这一边界。
- 拒绝超过 50 MB 的写入，也拒绝不包含完整 HTML 文档或可编辑正文根节点的内容。
- 静态资源请求必须解析在文章所在目录内，并拒绝路径遍历。
- 同一编辑器会话中不得覆盖第一次保存生成的原始备份；验证失败后也不得覆盖已有备份。
- 不得在 HTML、URL、终端参数、日志或回复中暴露 AppSecret。发布器使用 Windows DPAPI 为当前用户加密保存。
- 区分“测试权限”和“创建草稿”。只有获得用户明确授权时才能创建草稿。
